## Reranker → embedding-cosine substitution

The spec called for Cohere rerank v4.0 fast as the pair-quality score. The operator's Azure reference card pins this reranker at **`AZURE_RERANKER_MIN_INTERVAL_S=15.0`** (≈4 calls/minute) and **`AZURE_RERANKER_MAX_DOC_CHARS=200`** (the rerank document is truncated to 200 characters before scoring). On our typical 1200-token / ~5000-character chunks that's <5% of the content surface; the score would reflect how relevant the question is to the chunk header rather than to the chunk.

We replaced rerank with **embedding cosine similarity** using `text-embedding-3-small-meftun`. Embed the question, embed the full chunk text, compute cosine. Captures the entire chunk, runs in a single batched call per chunk, no per-call rate ceiling beyond standard Azure limits. The score lives in the same JSONL field role as `rerank_score` would have, written as `similarity_score` so downstream code knows what it actually is.

## Quality assessment

**Length profile:** mean question = 98 chars, mean answer = 313 chars. 0 answers under 60 chars; 0 over 700.

**Yes/no question check:** 0 of 50 questions start with a yes/no auxiliary (`is`/`are`/`does`/`can`/`will`/`should`/`must`). The spec forbids yes/no questions — if this is non-zero, tighten the system prompt for the full run.

**Low-similarity pairs (<0.5):** 6 of 50. These warrant a close read in the sample section above: are the questions actually off-topic, or is the embedding model missing topical overlap that a human reader would see?

**Honest read:** Sample pairs should be evaluated on three axes — (1) does the question sound natural and is it free of document-structure references? (2) is the answer fully derivable from the chunk? (3) does the answer paraphrase rather than verbatim-quote? Spot the sample chunks in the section above and score them on those axes before approving the full run.
